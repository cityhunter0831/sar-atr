## 3. 데이터셋 다운로드 가이드

### MSTAR → 신청해야 할 패키지

SDMS 공개 MSTAR 데이터는 4개 패키지(총 7개 CD)로 나뉩니다. **여러분의 4개 실험 기준으로 필요도를 정리하면:**

| 패키지 | 내용 | 필요 여부 |
|---|---|---|
| **MSTAR Targets** (Sept'95 collection) | T72, BMP2, BTR70, SLICY — El 15°/17° | **필수**: 실험 D(10클래스 holdout)의 BMP2/BTR70/T72 유일 출처 |
| **MSTAR/IU Mixed Targets** | 2S1, BRDM2, BTR60, D7, T62, ZIL131, ZSU23-4, SLICY — El 15/17/30/45° | **필수 (최우선)**: 실험 C(Figure1)의 2S1/BRDM2/ZSU23 @ El17°·El30°의 **유일한 출처**. 실험 D의 나머지 클래스도 여기서 |
| MSTAR Clutter | 클러터 패치 + 칩 | 선택: gengzhe2015가 Table4용 가공 이미지를 이미 제공. 시간 남으면 raw 클러터 분석용 |
| MSTAR/IU T-72 Variants | T72 변형 시리얼, El 15/17/30/45° | **불필요**: 4개 실험 어디에도 직접 사용 안 함(EOC 변형 분석에 스코프 밖) |

**→ 결론: "MSTAR Targets"와 "MSTAR/IU Mixed Targets" 두 패키지를 SDMS에서 함께 신청하세요.** 특히 Mixed Targets는 실험 C(El=30° 데이터)가 의존하는 유일한 소스라 빠지면 실험 C 자체가 불가능합니다. 신청 양식 작성 시 연구 목적란에 두 패키지 모두 명시하면 한 번에 처리됩니다.

## 5. 모듈 인터페이스 계약 — AI에게 "이 부분만" 맡기는 법

**문제 상황**: 두 사람(또는 각자의 AI 어시스턴트)이 같은 코드베이스를 동시에 건드리면, 서로의 미완성 코드 때문에 막히기 쉽습니다. **해결책: `core/`에 "계약(인터페이스)"을 먼저 정의 → 각 실험 모듈은 이 계약에만 의존 → 다른 모듈의 작성 여부와 무관하게 독립 개발/테스트 가능.**

### 5.1 `core/interfaces.py` (Day 1, 공동 작성 → 가장 먼저)

```python
from dataclasses import dataclass, field
from typing import Protocol, Optional
from torch import Tensor
from torch.utils.data import Dataset

@dataclass
class SARSample:
    image: Tensor          # [1, H, W], float32, [0,1] 정규화
    label: int              # 클래스 인덱스
    meta: dict = field(default_factory=dict)  # azimuth, elevation, class_name, source 등

class SARDataset(Dataset):
    """모든 데이터셋이 이 인터페이스를 따른다."""
    def __getitem__(self, idx) -> SARSample: ...
    def __len__(self) -> int: ...
    @property
    def class_names(self) -> list[str]: ...

class Augmentation(Protocol):
    """클러터전이/밝기보정/경계블렌딩 → 모두 동일 시그니처"""
    def __call__(self, image: Tensor, meta: dict) -> Tensor: ...

@dataclass
class TrainConfig:
    model_name: str            # "smpl" | "resnet18"
    num_classes: int
    epochs: int = 60
    batch_size: int = 128
    lr: float = 1e-3
    lr_decay_epoch: int = 50
    lr_decay_factor: float = 0.1
    loss_type: str = "lsm"     # "lsm" | "at"
    label_smoothing: float = 0.1
    seed: int = 0

@dataclass
class EvalResult:
    accuracy: float
    confusion_matrix: list[list[int]]
    per_class_accuracy: dict[str, float]
    auroc: Optional[float] = None
    tnr_at_95tpr: Optional[float] = None
```

### 5.2 `core/mock_data.py` (Day 1, 공동) → MSTAR 승인 대기 중에도 모든 모듈 테스트 가능

```python
import torch
from core.interfaces import SARSample, SARDataset

class MockSARDataset(SARDataset):
    """64x64 가짜 SAR 데이터 → 파이프라인/모델 검증용"""
    def __init__(self, n=200, num_classes=10, image_size=64):
        self.n, self.num_classes, self.image_size = n, num_classes, image_size

    def __len__(self):
        return self.n

    def __getitem__(self, idx):
        label = idx % self.num_classes
        img = torch.randn(1, self.image_size, self.image_size) * 0.3 + 0.5
        img[:, 28:36, 28:36] += 1.0  # 가짜 "표적" 반사 영역
        return SARSample(image=img.clamp(0, 1), label=label,
                          meta={"class_name": f"class{label}", "source": "mock"})

    @property
    def class_names(self):
        return [f"class{i}" for i in range(self.num_classes)]
```

## 6. SMPL + ResNet18 — 왜 둘 다, 어떻게

### 왜
- **SMPL은 논문의 "headline 결과" 모델**입니다 (Table3 56.6%→96.4%, +39.8%p → 여러분 슬라이드 9장 핵심 수치). ResNet18만 구현하면 이 핵심 주장을 직접 검증하지 못합니다.
- **ResNet18은 ImageNet 사전학습이 가능한 대형 모델**이라, "증가 효과"가 "사전학습/대형 구조 덕분"일 수 있습니다. 두 모델을 같은 조건에서 비교해야 "증가 기법 자체의 효과"를 분리할 수 있습니다(ablation).
- 교수님 입장에서는 "논문이 직접 설계한 경량 모델(SMPL)까지 구현하는가"가 **직접 재현 여부를 판단하는 기준**이 됩니다.

### 어떻게 → `core/models.py`

```python
import torch.nn as nn
import torchvision

class SMPL(nn.Module):
    """한 가이드라인 논문 코드 (LeNet 스타일 경량 CNN)"""
    def __init__(self, num_classes=10):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, 5, padding=2), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(16, 32, 5, padding=2), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(32, 64, 5, padding=2), nn.ReLU(), nn.MaxPool2d(2),
            nn.Conv2d(64, 128, 5, padding=2), nn.ReLU(),
        )
        self.classifier = nn.Sequential(
            nn.AdaptiveAvgPool2d(1), nn.Flatten(),
            nn.Linear(128, num_classes)
        )
    def forward(self, x):
        return self.classifier(self.features(x))


def get_resnet18(num_classes=10):
    """SAR 1채널 그레이스케일에 맞춰 첫 conv 수정"""
    model = torchvision.models.resnet18(weights=None)
    model.conv1 = nn.Conv2d(1, 64, kernel_size=7, stride=2, padding=3, bias=False)
    model.fc = nn.Linear(model.fc.in_features, num_classes)
    return model


def get_model(name: str, num_classes: int = 10) -> nn.Module:
    if name == "smpl":
        return SMPL(num_classes)
    if name == "resnet18":
        return get_resnet18(num_classes)
    raise ValueError(f"unknown model: {name}")
```

두 모델 모두 `forward(x) -> logits[B, C]`로 동일하므로, `core/train.py`는 `config.model_name`만 바꾸면 그대로 둘 다에 적용됩니다 (코드 분기 불필요).

### 어디에 적용하는가

| 실험 | 모델 | 비고 |
|---|---|---|
| **A (클러터 전이, Table4)** | **SMPL + ResNet18 둘 다 (필수)** | 4조건×2모델 = 8개 결과 → 비교표. 교수님 피드백의 직접 대상 |
| C (Figure1 밝기보정) | ResNet18 (논문 기준) + **SMPL (우리 확장)** | "밝기=학습특징" 문제가 경량모델에서 더/덜 심각한가 → 새로운 분석 포인트 |
| B, D | A에서 학습된 모델 재사용 (둘 중 하나로 충분, 시간 사정에 둘 다) | Grad-CAM/OOD는 백본 선택에 덜 민감 |

### 규칙
- `core/`는 **Day1에 둘이 함께 만들고 즉시 main에 merge** → 이후 변경 시 상대에게 미리 공지
- 각자 브랜치는 `core/`의 함수를 **호출만** 하고 수정하지 않음 (수정 필요시 PR + 리뷰)
- 커밋 prefix: `feat:`, `fix:`, `exp:`(결과), `docs:`

## 9. 최소 필수 실험 계획 및 완료 기준
